## 最终覆盖关系

必须按完整脚本执行后的 DOM 还原。基础 home() 被 pawpath 覆盖，再被 paw-auto-sort 排序包装；CSS 后续覆盖会取消首页卡片边界，形成连续的 #F9E9D8 画布。

- 最终首页只包含睡前清单及目标时间。旧首页统计卡、“体验 App 外提醒”按钮已被裁去，不应重新加回。
- 默认清单折叠显示当前事项；展开后为猫爪曲线路径；一键完成不等于进入晚安。
- records/report 重定向到 review，不是另外两张目标页面。
- customize 页面已退役；scheduleEditor 重启恢复到来源列表。
- 实际作息环时长范围为 5～1435 分钟、步进 5 分钟。前段遗留函数的 1～16 小时限制不作用于最终作息环。

## 架构与最小实现边界

- 独立本地演示数据仓库，默认七天记录明确归入 Demo 数据；不宣称真实睡眠监测。
- 业务状态使用独立 DataStore 键/模型，保留现有主题 DataStore 与错误恢复逻辑。
- ViewModel 持有日常配置、今晚状态和编辑事务；取消操作不能提前写入。
- Navigation 管理页面、返回来源及 Tab；恢复时不返回失效编辑草稿。
- Compose 自定义布局、Canvas/矢量图标、原图 Image；禁止 WebView 和整页位图。
- 不扩展原型未实现的后台监控、锁屏或覆盖其他应用能力。系统权限与模拟权限必须分离。

## 待明确的冲突与歧义

1. 候选 Android 工程在工作区外，需明确目标是否为 `E:/Term3.1/SleepCat`，或在当前工作区复制该工程继续开发。
2. HTML 没有深色主题，也没有主题入口；旧工程主题是已实现能力。建议保留基础设施，以原型浅色作为验收基准，主题界面是否保留需明确，不能擅自添加到原型设置页。
3. 原型提醒与权限明确为模拟。若要真实后台提醒属于新增能力，需单独定义权限和触发条件。
4. 最终首页移除了外部提醒入口，routine/晚安依旧存在但正常可见导航难以到达；不能自行插回按钮。可用测试路由验证这些存量页面。
5. 原型的“今晚跳过”没有完整按日重置，且“模拟下一次提醒”未检查 skipTonight；应记录为原型业务歧义。
6. 默认周记录为固定七条，没有自动生成真实昨晚记录的行为；按演示仓库实现。
7. 无深色原型、真实加载态或网络错误态，不自行设计；持久化失败需要最小反馈，不能静默成功。
